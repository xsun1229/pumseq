Introduction

This page summarizes cis-QTL mapping for pseudouridylation (%pU) using the binomial GLM count model on the 5-fold union sites (called in >= 1 fold; 12,416 sites), across the 50 genotyped cell lines. Unlike the linear tensorQTL approach — which builds a treated - input phenotype that is floored and quantile-normalized — the count model works directly on the raw converted-read counts, so no flooring or normalization is needed. The model and significance procedure are written up on the model page.

1. Phenotype: raw counts, modeled as binomial

For each site and cell line the phenotype is the pair of counts y = C (converted reads = %pU signal) out of n = C + T (read depth), extracted per cell line at the union sites. These enter the model directly as

\[ y_i \mid p_i \sim \text{Binomial}(n_i, p_i), \qquad \text{logit}(p_i) = \beta_0 + \beta_g G_i + z_i^\top\gamma . \]

Depth n_i is the binomial trial count, so low-coverage observations automatically carry less weight — there is no flooring, imputation, or quantile normalization step.

The pooled per-site modification rate is low (median ~5%), as expected for pseudouridylation — which is why the covariate transform below uses a site-specific pseudocount rather than a fixed one.

2. Covariates: M-value phenotype PCs

Following the IMAGE approach, covariates z_i are the top principal components of the M-values (log-odds of the modification rate). To avoid shrinking every site toward 50% (a fixed 1:1 pseudocount would), we use a site-specific pseudocount (pi_s, 1 - pi_s), so each site is shrunk toward its own mean rate:

\[ M_{si} = \log_2\frac{y_{si} + \pi_s}{\,n_{si} - y_{si} + (1-\pi_s)\,}, \qquad \pi_s = \frac{\sum_i y_{si}}{\sum_i n_{si}} . \]

Each site is standardized, PCA is taken across cell lines, and the top k PC scores are used as covariates. The number of PCs k is swept (below).

3. QTL mapping approach

For each (site, cis-SNP) pair the genotype effect beta_g is tested with a likelihood-ratio test (LRT): fit the full model (with the cis-SNP) and the covariates-only null model, compare log-likelihoods. A faster Rao score test (null fit once per site, every cis-SNP a vectorized computation) was tried first but found unreliable at exactly the sites that matter most — it can be spuriously overconfident near separation boundaries (Hauck-Donner effect) or correctly refuse to answer (NA) exactly where the LRT finds its strongest signals. Confirmed on real data: only 57.4% same lead SNP, rank correlation 0.875 (nominal p) between the two tests. See the model page for the full comparison. The LRT is more expensive (a full-model refit per cis-SNP, not one null fit per site), made feasible genome-wide by splitting the permutation scan across chromosomes (and, for a few unusually dense loci, further chunks) as parallel SLURM jobs. Significance follows the standard human cis-QTL procedure:

  1. Per-SNP nominal p from the score test.
  2. Within-site correction — the FastQTL/tensorQTL permutation beta-approximation: permute the phenotype 1000x, fit a Beta distribution to the null min-p, read off one adjusted p per site.
  3. Across-site correction — BH-FDR (and q-values) over the per-site p.

Two things are swept:

  • Covariate PCs: 3, 5, 7, 10, 15, 20.
  • cis-window: 5 kb, 20 kb, 50 kb, 100 kb.

That is a 6 x 4 grid, each cell a separate scan.

5. Calibration check: the LRT is better calibrated than the score test, but still not perfect

We permute the phenotype and covariates together across the 50 cell lines (breaking the genotype link, keeping phenotype-covariate pairing; genotype stays fixed at its true per-individual values), 5 seeds, and check whether the nominal p-values are Uniform(0,1) — via the genomic-inflation factor lambda (median chi-square / 0.455; should be ~1 under a calibrated null) and a QQ-plot. Same negative-control permutation as the linear model. Run at the peak config (5 kb, 3 PCs).

The LRT is better calibrated than the score test, but neither reaches lambda~1. LRT: real lambda=5.55, permuted-null lambda=~3.28 (range 2.93-3.44). Score test (for comparison): real lambda=7.54, permuted-null ~3.8. Switching to the LRT fixed the test-specific numerical failure modes (catastrophic cancellation, the Hauck-Donner effect near separation — see the model page), but the permuted-null lambda staying well above 1 even for the LRT points to something the test itself cannot fix: the plain binomial model doesn’t account for real overdispersion in the data. A separate LRT for \(H_0:\phi=0\) finds ~22% of sites significantly overdispersed (FDR<0.05) — see the beta-binomial page, whose score/LRT divide by the correct inflated variance and calibrates much closer to 1 (permuted-null ~1.13-1.17).

Practical consequence: more PCs will not fix this (overdispersion is a variance mis-specification, not a mean confounder — the monotonic decline in QTL counts with more PCs in Section 4 reflects spent degrees of freedom, not improving calibration), and the per-site QTL calls above use the permutation beta-approximation (self-calibrating against this same inflation), so the FDR counts are more robust than the raw nominal lambda suggests — but the residual inflation here is the reason the beta-binomial model is worth treating as the more complete final model, not just the binomial with a better test.
